# Windows デバイスドライバ INF インストーラ コンソールアプリケーション

## 機能概要
INF ファイルを使用して Windows デバイスドライバを宣言的にインストールするスタンドアロンコンソールアプリケーション。開発者がインストール処理（CopyFiles, AddReg, ほか）とサービス登録（.Services）を独立してテストでき、他のインストーラソリューションに統合可能な再利用可能ロジックを提供します。実装は Microsoft の最新ベストプラクティスに従い、HLK テストとの互換性を確保します。

## 共通必須ルール（最上位・spec-kit 全体）
- UnitTest と（CI で走る）IntegrationTest は、実 OS 環境（レジストリ、SetupAPI、サービス、ドライバ、デバイス等）を変更しない。
  - OS 依存処理は必ずインターフェースで抽象化し、テスト時はスタブ／モックを注入する。
  - 本プロジェクトでは SetupAPI を ISetupApiWrapper で抽象化し、本番は SetupApiWrapper、テストは SetupApiStub を用いる。
  - IntegrationTest でもスタブを使用し、管理者権限や実 OS 変更を要求しない。
- 実 OS 環境を変更する検証（レジストリ操作、ファイルコピー、サービス登録、PnP 連携 等）は「OS 環境テスト」として専用テスト環境でのみ実施し、CI では実行しない。
  - 実行観点・手順は関連ドキュメント（os-integration-test-spec / test-environment-setup）に従う（当 spec が最上位だが、詳細手順は補助資料とする）。
- 新規に OS を変更する機能を追加する場合、抽象化と DI により Unit/Integration でスタブ置換可能にすること。
- テストは管理者権限を前提としない（OS 環境テストを除く）。

## ユーザーシナリオ & テスト *(必須)*

### 主要なユーザーストーリー
Windows デバイスドライバ開発者として、開発中に INF の宣言的インストールをテストし、エンドユーザーに信頼性の高いインストールメカニズムを提供するために、INF ベースのドライバをサイレントで適用できるコンソールアプリケーションが必要です。

### 受け入れシナリオ
1. 前提条件: 有効な INF ファイルとドライバパッケージが存在する。実行時: ユーザーが INF ファイルパスとセクション名（省略時 DefaultInstall）を指定して実行する。期待結果: INF の宣言的指示（CopyFiles, AddReg 等）が適用され、必要に応じて再起動要求が返される。
2. 前提条件: 無効または破損した INF ファイルが存在する。実行時: ユーザーがインストールを試行する。期待結果: アプリケーションが問題を説明する明確なエラーメッセージを日本語で表示する。
4. 前提条件: 同一セクションが既に適用済み。実行時: ユーザーが同じセクションを再適用する。期待結果: アプリケーションが既存状態を検出し、適切な選択肢（更新、再適用、またはスキップ）を提供する。
5. 前提条件: アプリケーションがインストールを完了する。実行時: プロセスが終了する。期待結果: アプリケーションがインストール状況を表示し、検証のためのガイダンスを提供する。

## 要件 *(必須)*

### 機能要件
- FR-001: システムは提供された INF ファイルを使用して宣言的インストールを実行しなければならない
- FR-004: システムは明確なステータスメッセージとエラー報告を日本語で提供しなければならない
- FR-006: システムは HLK 互換性のために Microsoft 推奨のインストール実践に従わなければならない
- FR-007: システムはコマンドラインインターフェースを提供しなければならない
- FR-008: システムは前提条件とシステム要件をユーザーに表示しなければならない
- FR-009: システムは他のインストーラで再利用できる分離可能なコンポーネントとして実装しなければならない
- FR-010: システムはトラブルシューティングのためにインストール活動をログに記録しなければならない
- FR-012: システムはサイレントモードのインストールをサポートしなければならない
- FR-013: システムは実行可能な次のステップとともに明確な成功/失敗フィードバックを提供しなければならない
- FR-014: システムはインストールロジック内では英語の技術ログ、UI では日本語のメッセージを分離して提供しなければならない
- FR-015: ファイルシステム・ミニフィルタ、クラス単位のフィルタ、ソフトウェア（仮想）デバイスなど、ハードウェア I/O デバイスを直接制御しないドライバに限定する

### 非機能要件
- NFR-001: アプリケーションは Windows 10 および Windows 11 と互換性がなければならない
- NFR-002: アプリケーションは .NET 10 フレームワークをターゲットにしなければならない
- NFR-003: インストールは合理的な時間制限内で完了し、超過時はタイムアウトとしてエラーにしなければならない
- NFR-004: アプリケーションは日本語でユーザーインターフェースを提供しなければならない
- NFR-005: コードは他プロジェクトへのロジック抽出が可能な構造でなければならない

### 主要エンティティ *(データが関与する場合に含める)*
- INF ファイル: インストール手順とメタデータを含む
- ドライバパッケージ: 必要なファイル群と INF を含む
- インストールセッション: ログとステータスを持つ単一実行

## 技術的制約
- HLK 要件に準拠
- 2024 年時点のベストプラクティスに準拠
- 署名済み/未署名ドライバ双方で動作（適切な警告）

## 依存関係と前提条件
- Windows の適切な SetupAPI が利用可能
- 管理者権限
- INF が仕様に従うこと
- 対象 OS/クラス/インストールセクションが INF と整合していること
