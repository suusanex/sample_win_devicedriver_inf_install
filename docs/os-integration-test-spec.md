# OS環境統合テスト仕様書

## 概要
このドキュメントは、実際のWindowsOS環境を使用してドライバインストール機能をテストするための仕様を定義します。これらのテストは実OS環境を変更するため、専用のテスト環境で実行する必要があります。

## テスト環境要件

### 必須要件
- Windows 10/11 Professional 以上（テスト署名モードを有効にできる）
- 管理者権限でのアプリケーション実行
- テスト用の物理または仮想マシン（本番環境ではない）
- .NET 10 Runtime
- テスト用のドライバパッケージ（署名済み）

### 推奨環境構成
- 仮想マシン環境（復元可能）
- システム復元ポイントの作成
- テスト前のレジストリバックアップ
- Windows テストモード（bcdedit /set testsigning on）

## テスト観点とテストケース

### 1. レジストリ操作テスト

#### 1.1 レジストリ書き込み権限テスト
**目的**: 管理者権限の有無による動作確認  
**実行条件**: 標準ユーザーとして実行  
**期待結果**: アクセス拒否エラーが適切に処理される  
**確認項目**:
- エラーコード 5 (ERROR_ACCESS_DENIED) の検出
- 日本語エラーメッセージの表示
- ログエントリの適切な記録

#### 1.2 レジストリキー作成テスト
**目的**: INFファイルのレジストリセクション処理確認  
**実行条件**: 
- 管理者権限で実行
- レジストリ操作を含むINFファイルを使用
**期待結果**: 指定されたレジストリキーが正しく作成される  
**確認項目**:
- HKLM\SOFTWARE配下のキー作成
- 文字列値、DWORD値の正確な設定
- レジストリ作成ログの記録

#### 1.3 レジストリ削除・クリーンアップテスト
**目的**: インストール後のクリーンアップ動作確認  
**実行条件**: アンインストール処理の実行  
**期待結果**: 作成されたレジストリエントリが適切に削除される  
**確認項目**:
- キーの完全削除
- 残存エントリの有無確認
- クリーンアップログの記録

### 2. ファイルシステム操作テスト

#### 2.1 ドライバファイルコピーテスト
**目的**: INFファイルによるファイルコピー動作確認  
**実行条件**: 
- CopyFilesセクションを含むINFファイル
- System32\drivers フォルダへの書き込み権限
**期待結果**: ドライバファイルが正しい場所にコピーされる  
**確認項目**:
- ファイルコピー先の正確性
- ファイル属性・権限の設定
- コピー処理ログの記録

#### 2.2 システムディレクトリアクセステスト
**目的**: システム保護されたディレクトリへのアクセス確認  
**実行条件**: System32配下への書き込み試行  
**期待結果**: 適切な権限チェックとエラーハンドリング  
**確認項目**:
- UAC昇格の動作
- アクセス拒否時のエラー処理
- セキュリティエラーのログ記録

### 3. SetupAPI統合テスト

#### 3.1 実際のINFファイル処理テスト
**目的**: Windows標準のSetupAPIとの統合確認  
**実行条件**: 
- 有効なINFファイル（Microsoft署名済み推奨）
- 管理者権限での実行
**期待結果**: SetupAPIが正常に動作し、処理が完了する  
**確認項目**:
- SetupOpenInfFile の成功
- SetupInstallFromInfSection の正常終了
- API呼び出しログの記録

#### 3.2 無効なINFファイル処理テスト
**目的**: 破損・不正なINFファイルに対するエラーハンドリング確認  
**実行条件**: 
- 意図的に破損させたINFファイル
- 不正な形式のINFファイル
**期待結果**: 適切なエラー検出と処理  
**確認項目**:
- 構文エラーの検出
- セクション不存在エラーの処理
- 詳細なエラー情報の提供

#### 3.3 ドライバ署名検証テスト
**目的**: デジタル署名の検証動作確認  
**実行条件**: 
- 署名済みドライバパッケージ
- 未署名ドライバパッケージ
**期待結果**: 署名状態に応じた適切な処理  
**確認項目**:
- 署名済みドライバの正常インストール
- 未署名ドライバのエラー処理
- テストモードでの動作確認

### 4. サービス制御テスト

#### 4.1 Windowsサービス登録テスト
**目的**: INFファイルのServicesセクション処理確認  
**実行条件**: 
- Services セクションを含むINFファイル
- サービス制御マネージャーへのアクセス権限
**期待結果**: Windowsサービスが正しく登録される  
**確認項目**:
- サービスの登録確認（services.msc）
- サービス設定の正確性
- サービス開始・停止の動作

#### 4.2 既存サービス競合テスト
**目的**: 同名サービス存在時の動作確認  
**実行条件**: 既に同名サービスが存在する環境  
**期待結果**: 適切な競合検出とエラー処理  
**確認項目**:
- 競合の検出
- エラーメッセージの内容
- ロールバック処理の動作

### 5. デバイス管理統合テスト

#### 5.1 プラグアンドプレイ統合テスト
**目的**: PnPマネージャーとの統合動作確認  
**実行条件**: 
- 実際のハードウェアデバイス
- または仮想デバイス
**期待結果**: デバイスマネージャーでドライバが認識される  
**確認項目**:
- デバイスマネージャーでの表示
- ドライバの状態確認
- イベントログの記録

#### 5.2 ドライバ更新テスト
**目的**: 既存ドライバの更新動作確認  
**実行条件**: 
- 古いバージョンのドライバがインストール済み
- 新しいバージョンのINFファイル
**期待結果**: ドライバが正しく更新される  
**確認項目**:
- バージョン番号の更新
- ファイルの置き換え
- 更新履歴の記録

### 6. エラー処理・復旧テスト

#### 6.1 部分的失敗からの復旧テスト
**目的**: インストール途中でのエラー処理確認  
**実行条件**: 
- 意図的にエラーを発生させる環境
- （ディスク容量不足、ファイルロック等）
**期待結果**: 適切なロールバック処理  
**確認項目**:
- 部分的に作成されたファイル・レジストリの削除
- エラー状態の詳細ログ記録
- システム状態の復旧

#### 6.2 権限昇格失敗テスト
**目的**: UAC拒否時の動作確認  
**実行条件**: UAC プロンプトでの拒否操作  
**期待結果**: 権限不足エラーの適切な処理  
**確認項目**:
- 権限エラーの検出
- ユーザーフレンドリーなエラーメッセージ
- 処理の安全な中断

## テストデータ

### テスト用INFファイル
1. **basic_driver.inf** - 基本的なファイルコピーのみ
2. **registry_driver.inf** - レジストリ操作を含む
3. **service_driver.inf** - サービス登録を含む
4. **complex_driver.inf** - 全機能を含む包括的テスト
5. **invalid_syntax.inf** - 構文エラーを含む
6. **missing_section.inf** - 必須セクション欠落

### テスト用ドライバファイル
1. **test_signed.sys** - テスト署名済みドライバ
2. **test_unsigned.sys** - 未署名ドライバ
3. **test_malformed.sys** - 破損ドライバファイル

## テスト実行手順

### 事前準備
1. テスト環境の復元ポイント作成
2. テストモードの有効化 (`bcdedit /set testsigning on`)
3. 管理者権限でのコマンドプロンプト起動
4. ベースラインのレジストリ・ファイルシステム状態の記録

### 実行手順
1. 各テストケースを順次実行
2. 実行後の状態確認
3. ログファイルの収集と分析
4. 必要に応じてシステム復元

### 事後処理
1. 作成されたファイル・レジストリエントリの削除
2. テストモードの無効化（必要に応じて）
3. システム状態の検証
4. テスト結果レポートの作成

## 注意事項

### セキュリティ
- 本番環境では絶対に実行しない
- テスト用証明書の適切な管理
- テスト後のクリーンアップの徹底

### 法的考慮事項
- テスト用ドライバの配布・使用権限
- サードパーティ製ドライバの使用許諾
- 企業環境でのテスト実行ポリシー遵守

### トラブルシューティング
- システム復旧手順の準備
- 緊急時の連絡先・手順の明確化
- テスト環境の分離確保
